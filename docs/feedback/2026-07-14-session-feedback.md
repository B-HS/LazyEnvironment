# 사용자 피드백 교정 기록 (2026-07-14 세션)

> 형식: 지적 / 왜 문제였나 / 어떻게 고쳤나 / 언제 적용하나(적용 조건).

## 1. "버튼에 눈깔은 왜 달아둔거야"
- 왜: 액션 버튼에 프리뷰 힌트용 eye 아이콘을 덧붙인 것이 시각 노이즈. 프리뷰는 최초 실행 시 강제 시트 + 우클릭 메뉴로 이미 접근 가능.
- 고침: 아이콘 제거.
- 적용: 버튼에 보조 아이콘을 덧붙이기 전에 "이미 다른 진입점이 있는가"를 먼저 확인. 장식성 아이콘 금지.

## 2. "설명이 너무 부족하잖아" + 수동 단계 개행/번역
- 왜: 레시피 summary·manualSteps가 형식적 1줄이었고, 레시피 데이터는 영어 고정(초기의 "UI 크롬만 로컬라이즈" 결정이 사용자 기대와 어긋남).
- 고침: 20종 요약 재작성 + 54개 수동 단계(선행 레시피→수동 절차→export→인증→주의), `Text(LocalizedStringKey(...))` 렌더로 콘텐츠도 xcstrings 번역, `fixedSize`로 줄바꿈.
- 적용: 사용자 노출 데이터 문자열은 처음부터 로컬라이즈 경로로 설계. "설명"은 실제로 따라 할 수 있는 수준까지.

## 3. 자동 디스크 재검사 삭제 ("디스크 수명")
- 왜: 주기/시작/wake 자동 du 스캔은 사용자에게 비용(디스크 I/O)이었음. 편의 기능이 자원 소모를 정당화하지 못함.
- 고침: 자동 스캔 전부 제거, 수동 트리거만. 측정 시각은 저장·표시.
- 적용: 백그라운드 자동 작업을 넣을 때는 자원 비용을 먼저 따지고 기본 off/수동을 고려.

## 4. relocate 제안 → 방향 전환
- 왜: move+symlink vs env 재지정 옵션을 제시했으나 사용자는 기능 자체를 원치 않음 — "삭제를 제대로 + 설치 경로 지정을 제대로"가 진짜 요구.
- 고침: 외부 설치 전용 uninstall(도구 네이티브 우선) + 레시피별 customDevHome.
- 적용: 기능 제안이 거절되면 대안을 다시 팔지 말고 사용자가 재정의한 요구를 그대로 구현.

## 5. Dock 아이콘 / 팝오버 UI "구려"
- 왜: 메뉴바 상주인데 창 없이 Dock 아이콘 잔존(전환 로직 누락 케이스), 팝오버는 콘텐츠 빈약+사이징 버그.
- 고침: willClose 중앙 관찰로 accessory 전환, 팝오버 재디자인(상태 칩·디스크 상위 바·설정 진입)+sizingOptions.
- 적용: 메뉴바 앱 UX 관례(창 없으면 Dock 없음)를 기본값으로. NSHostingController 팝오버는 항상 sizingOptions 지정.

## 6. 계층 일관성 ("python만 계층이면 pnpm bun npm도")
- 왜: 한 카테고리에만 계층을 도입하면 분류 체계가 어중간해짐.
- 고침: JS 계열도 node-nvm 하위로 이동(+npm 신설), 분류 전체를 계층 기준으로 재정렬.
- 적용: 구조적 패턴(계층·상태·색 등)을 도입할 때는 카탈로그 전체에 일관 적용 여부를 먼저 결정.

## 7. 폴더명 오타 "사용자 선택으로 유지" → "오타도 수정해놔"
- 왜: 초기에 무응답을 '유지 선택'으로 기록했으나 사용자 의도는 수정이었음.
- 고침: `lazy-enviroment` → `lazy-environment` 리네임 + 레포 내 참조 정리 + 전체 재검증.
- 적용: 무응답은 결정이 아님 — 문서에 "사용자 선택"이라 적기 전에 명시 확인.

## 8. (세션 전반) 서버는 어디갔어 / turso / 셀프 호스트 / 언어 3개
- 적용 교훈: PRD 로드맵(v2 후순위)을 근거로 미룬 것을 사용자는 "누락"으로 인식 — 큰 덩어리를 뒤로 미룰 때는 로드맵상 위치를 보고에 명시하고, 사용자가 원하면 즉시 당긴다.
